# US Stocks Challenge Security Architecture

## 1. Signal-Only Enforcement (Honesty Contract)
Система работает строго в режиме сигнального советника:
1. `execution.mode: disabled` в `config/us_stocks_challenge.yaml`.
2. `DisabledExecutor` логирует намерение и выбрасывает `ExecutionDisabledError` при любой попытке вызова `submit()`.
3. `usstocks.guards.assert_auto_trading_allowed` принудительно завершает процесс (`SystemExit 2`), если исполняющие модули запускаются под профилем `us_stocks_challenge`.

---

## 2. Защита Telegram команд и Replay Protection
1. **Авторизация (Fail-Closed)**: команды `/us_*` доступны только пользователю с ID, указанным в `TELEGRAM_ADMIN_CHAT_ID`. Запросы от сторонних пользователей игнорируются с блокирующим уведомлением.
2. **Inline Confirmation**: мутации состояния (PnL, стоп-день, сброс позиции) применяются **только** после нажатия кнопки «✅ Принял».
3. **Replay Protection**:
   - Каждое действие генерирует криптографический nonce (`uuid.uuid4().hex[:12]`).
   - Использованные nonces сохраняются в памяти с временными метками.
   - Повторные запросы с тем же nonce немедленно отклоняются.
   - Срок жизни действия (TTL) ограничен 300 секундами.
   - Устаревшие апдейты Telegram (>600 секунд) отбрасываются диспетчером.

---

## 3. Защита данных и инъекции
1. **Символы**: `validate_symbol` проверяет длину (1-10 символов) и формат регулярным выражением `^[A-Z0-9.\-]{1,10}$`, отсекая SQL-инъекции, XSS и спецсимволы.
2. **SQLite**: все запросы в `UsJournal` используют параметризованные SQL-биндинги `?` без форматирования строк.
3. **Файловая система**: экспорт CSV выполняется атомарно через временные файлы `.tmp.<pid>` в выделенной директории.
4. **Секреты**: токены и пароли считываются только из переменных окружения / `.env`. Файл `.env` исключён из репозитория через `.gitignore`.
