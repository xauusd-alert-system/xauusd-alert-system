## 3. Ключевые концепции

### Концепция 1: MQL5 как C++-подобный компилируемый язык с ООП
**Определение:** MQL5 сочетает черты предметно-специфического и универсального языка; поддерживает ООП (классы, наследование, виртуальные методы, шаблоны), статическую типизацию, компиляцию в байткод, выполняемый внутри защищённой среды терминала. Автор формулирует «MQL5 — это sort of C±±» (стр. 15).
**Контекст:** Части 2–3 дают полный арсенал: типы (включая datetime, color, enum, void), ссылки/указатели объектов, перегрузку операций, исключения, шаблоны. Это фундамент для архитектуры любого EA-проекта.

### Концепция 2: Типы MQL-программ и модель исполнения
**Определение:** Пять типов программ — Expert Advisor, индикатор (в т.ч. кастомный), скрипт, сервис, библиотека — с разными точками входа и жизненным циклом (5.1, стр. 612+). Все MQL-программы однопоточны; события обрабатываются последовательно в порядке поступления (стр. 1170).
**Контекст:** EA может обходиться без OnTick — доступны OnTimer, OnBookEvent, OnChartEvent; очередь событий не копит дубли OnTick, если обработка ещё идёт. Для мультивалютности OnTick приходит только на символ графика — предлагаются spy-индикаторы (`EventTickSpy.mq5`) или подписка на стакан (`MarketBookQuasiTicks.mq5`) (стр. 1170–1171).

### Концепция 3: Timeseries API
**Определение:** Семейство функций доступа к историческим рядам: `Bars`, `iBarShift`, `CopyRates/CopyTime/CopyOpen/...`, структуры `MqlRates` и `MqlTick`, поиск max/min в серии (5.3, стр. 637–674).
**Контекст:** Копирование массивов котировок, чтение по индексу, работа с реальными тиками — база любых расчётов признаков для ML и сигналов.

### Концепция 4: Кастомные индикаторы и их использование
**Определение:** OnCalculate-модель построения индикаторов (5.4, стр. 675+), буферы, стили отрисовки; использование готовых индикаторов через хэндлы `iRSI/iMACD/...` + `CopyBuffer` (5.5, стр. 762+).
**Контекст:** Паттерн «создал хэндл → асинхронно получил буфер» критичен для понимания: данные индикаторов приходят не мгновенно; требуется проверка готовности (BarsCalculated). Прямо применимо к фичагенерации XAUUSD.

### Концепция 5: Торговая модель MT5 — order/deal/position
**Определение:** Разделение сущностей: ордер (запрос), сделка (исполнение), позиция (итог нетто/хедж). Типы торговых операций, типы ордеров (market/pending: Buy/Sell/Stop/Limit/StopLimit), режимы исполнения по цене и объёму, истечение отложек (6.4.1–6.4.7, стр. 1170–1178).
**Контекст:** Неттинг vs хеджирование определяет логику учёта позиций; понимание транзакционной модели — обязательное условие корректного EA.

### Концепция 6: Трейд-запросы и предпроверки
**Определение:** Ядро исполнения — структуры `MqlTradeRequest` / `MqlTradeCheckResult` / `MqlTradeResult`, функции `OrderCheck` (валидация), `OrderSend` / `OrderSendAsync` (отправка) (6.4.9–6.4.13, стр. 1196–1214).
**Формулы предрасчёта:** `OrderCalcMargin` — маржа под будущий ордер (6.4.7, стр. 1178–1190); `OrderCalcProfit` — оценка профита/убытка операции (6.4.8, стр. 1190–1196).
**Контекст:** Паттерн безопасной торговли: расчёт маржи → OrderCheck → OrderSend → анализ retcode → обработка частичного исполнения.

### Концепция 7: Управление позициями
**Определение:** Полный жизненный цикл: покупка/продажа (6.4.14), модификация SL/TP (6.4.15), трейлинг-стоп (6.4.16), полное/частичное закрытие (6.4.17), закрытие встречных позиций (6.4.18), работа с отложенными ордерами: установка/модификация/удаление (6.4.19–6.4.21), выборка активных ордеров/позиций/сделок и их свойства (6.4.22–6.4.32).
**Контекст:** Готовые рецепты для слоя исполнения xauusd-alert-system: трейлинг и частичные закрытия описаны с кодом (стр. 1229–1290).

### Концепция 8: События торгового окружения
**Определение:** `OnTradeTransaction` (стр. 1359) — асинхронное уведомление о каждой транзакции; `OnTrade` (стр. 1391); мониторинг изменений торгового окружения (6.4.37, стр. 1399); синхронные и асинхронные запросы (6.4.35, стр. 1378).
**Контекст:** Корректная архитектура алерт-системы строится на OnTradeTransaction (сигналы о исполнении/закрытии) вместо поллинга.

### Концепция 9: Мультивалютные EA
**Определение:** Построение EA, торгующих несколькими символами (6.4.38, стр. 1429–1444): сбор тиков с чужих символов, синхронизация данных, ограничения.
**Контекст:** Прямо релевантно, если alert-система будет отслеживать корзину инструментов (XAUUSD + коррелирующие).

### Концепция 10: Тестирование и оптимизация
**Определение:** Генерация тиков в тестере (6.5.1, стр. 1450: 4 режима от OHLC до реальных тиков); время в тестере (6.5.2); визуализация (6.5.3); мультивалютный тест (6.5.4); критерии оптимизации (6.5.5); `TesterStatistics` — доступ к финансовой статистике прогонов (6.5.6, стр. 1466); событие `OnTester` — кастомный критерий (6.5.7, стр. 1478); автонастройка параметров `ParameterGetRange/SetRange` (6.5.8); группа OnTester-событий для управления оптимизацией (6.5.9); фреймы — передача данных от агентов в терминал (6.5.10–6.5.11); директивы препроцессора для тестера (6.5.12); `TesterHideIndicators` (6.5.13); эмуляция вводов/выводов средств (6.5.14); `TesterStop` (6.5.15); большой пример EA (6.5.16, стр. 1515–1558); математические расчёты без котировок (6.5.17); отладка/профилирование (6.5.18); ограничения функций в тестере (6.5.19).
**Контекст:** Полная методология валидации торговых систем: от качества тиков до кастомных критериев оптимизации и сбора распределений через фреймы.

### Концепция 11: Экономический календарь
**Определение:** Встроенная БД макрособытий: точное время выхода, важность, валюта влияния, прогноз/факт; программный доступ из MQL5 (7.3, стр. 1689+).
**Ограничения (важно):** функции календаря **не работают в тестере** (ошибка 4014 FUNCTION_NOT_ALLOWED); время событий — серверное (TimeTradeServer) с зоной/DST; для бэктеста новостных стратегий требуется собственная история событий (стр. 1690).
**Контекст:** Для xauusd-alert-system это штатный механизм news-фильтра в live-режиме.

### Концепция 12: Сетевые функции
**Определение:** Три группы (7.5, стр. 1795): высокоуровневые `SendFTP`/`SendMail`/`SendNotification` (push-уведомления на мобильный); средняя — `WebRequest` (HTTP/HTTPS GET/POST); низкоуровневые — `Socket*` (TCP, включая TLS).
**Ограничения:** whitelist URL в настройках терминала (программно менять нельзя); только клиентские соединения — сервер на MQL5 не построить (стр. 1795–1796); push работает только на счёт/терминал пользователя.
**Контекст:** Это готовый инструментарий доставки алертов: push-уведомления, e-mail, HTTP-хуки (Telegram-бот через WebRequest), TCP-мост к внешнему сервису.

### Концепция 13: SQLite и данные
**Определение:** Встроенная реляционная СУБД SQLite в MQL5 (7.6, стр. 1839+): SQL-запросы, таблицы, транзакции; плюс файловый API части 4.
**Контекст:** Журналирование сигналов, хранение состояния алерт-системы, история отправленных уведомлений — без внешних сервисов.

### Концепция 14: Python-интеграция
**Определение:** Пакет `MetaTrader5` для Python (7.9, стр. 1998+): установка (`pip install MetaTrader5`), аналоги MQL5-функций (терминал, счёт, котировки, тики, стакан, ордера, позиции, сделки), отправка ордеров из Python (7.9.12, стр. 2024), обмен через RPC/ipykernel.
**Ограничения:** нет событий (OnTick/OnTradeTransaction) — цикл опроса; нельзя получить значения индикаторов; отдельная настройка «отключить автоторговлю через Python» (ошибка 10027) (стр. 1998–2000).
**Контекст:** Идеальный мост для ML-пайплайна: Python получает данные/историю из терминала, делает инференс модели и отправляет торговые команды.

### Концепция 15: OpenCL и кастомные символы
**Определение:** Встроенная поддержка OpenCL для параллельных вычислений (7.10, стр. 2038+); кастомные символы с собственной историей (7.2, стр. 1624+).
**Контекст:** OpenCL — ускорение инференса нейросети в EA (в связке с книгой №1); кастомные символы — синтетические инструменты и нестандартные таймфреймы (Renko/PAF упоминаются на стр. 1689–1690).

## 4. Математические формулы

Книга — программная документация: математика присутствует точечно, в виде расчётных функций платформы. Формулы в тексте не нумерованы и в основном заданы алгоритмически (кодом); ключевые места:

### Формула 1: Маржа под будущий ордер — OrderCalcMargin (стр. 1178–1190)
```latex
\text{Margin} = \frac{\text{Volume} \times \text{ContractSize} \times \text{Price}}{\text{Leverage}} \times K_{\text{symbol}}
```
**Где:** Volume — объём в лотах; ContractSize — размер контракта символа; Leverage — плечо счёта; K — коэффициент маржи инструмента (SYMBOL_MARGIN_*).
**Применение:** предпроверка возможности открыть позицию до отправки запроса; для XAUUSD (contract 100 oz) расчёт маржи обязателен при малых депозитах.
**Статус:** точная формула задаётся платформой и описана текстом/кодом; сверить с разделом для ручной проверки.

### Формула 2: Оценка прибыли операции — OrderCalcProfit (стр. 1190–1196)
```latex
\text{Profit} = (\text{Price}_{close} - \text{Price}_{open}) \times \text{Direction} \times \frac{\text{Volume}\times\text{ContractSize}}{\text{TickSize}} \times \text{TickValue}
```
**Где:** Direction = +1 (buy) / −1 (sell); TickSize — минимальный шаг цены; TickValue — стоимость тика в валюте счёта.
**Применение:** прогноз P/L до входа; построение риск-лимитов алерт-системы (ожидаемый убыток при срабатывании SL).

### Формула 3: Стоимость пункта и пересчёт объёма (по контексту гл. 6.1/6.4)
```latex
\text{PointValue} = \text{TickValue} \times \frac{\text{Point}}{\text{TickSize}}
```
**Применение:** пересчёт стопов в деньги и объёма от риска (risk-based sizing) для XAUUSD.

### Формула 4: Статистика тестера — TesterStatistics (стр. 1466–1478)
Платформенные метрики, доступные кодом: `STAT_PROFIT`, `STAT_PROFIT_FACTOR`, `STAT_EXPECTED_PAYOFF`, `STAT_EQUITY_DDRELATIVE`, `STAT_TRADES` и др. — фактически стандартный набор торговых метрик:
```latex
PF=\frac{\sum \text{Profit}}{\sum \text{Loss}},\quad
EP=\frac{\text{NetProfit}}{N_{\text{trades}}}
```
**Применение:** программный доступ к метрикам внутри OnTester для кастомных критериев оптимизации.

### 7.3 Ключевые выводы (bullet points)

- MQL5 — полноценный ООП-язык уровня C++-семейства с компиляцией и безопасной средой исполнения; «бытовое» представление о нём как о скриптовом языке устарело.
- Ядро исполнения торгового робота — транзакционная модель: MqlTradeRequest → OrderCheck → OrderSend(Async) → MqlTradeResult → OnTradeTransaction; поллинг состояния считается антипаттерном.
- Предпроверки обязательны: OrderCalcMargin и OrderCalcProfit позволяют оценить маржу и P/L до входа, предотвращая отказы NO_MONEY и неоправданные риски.
- Событийная модель богаче OnTick: OnTimer, OnBookEvent (стакан), OnChartEvent, OnTrade/OnTradeTransaction; EA однопоточны, дубли OnTick не копятся в очереди.
- Мультивалютность требует специальных решений (spy-индикаторы, стакан), т.к. OnTick генерируется только для символа графика.
- Тестирование — методология, а не кнопка: 4 режима генерации тиков (финальная валидация — на реальных тиках), TesterStatistics для программного доступа к метрикам, OnTester для кастомных критериев, фреймы для сбора распределений от агентов.
- Экономический календарь доступен из кода, но не работает в тестере (4014) и живёт в серверном времени с DST — новостной фильтр в live даётся «из коробки», для бэктеста нужна собственная история новостей.
- Доставка уведомлений уже встроена: SendNotification (push), SendMail (email), SendFTP; WebRequest покрывает HTTP-интеграции (с whitelist в настройках), Sockets — TCP/TLS (только клиент).
- Python-пакет MetaTrader5 даёт полный доступ к данным и торговле из Python, но без событийной модели и без значений индикаторов — для ML-пайплайна данные нужно кэшировать/рассчитывать самостоятельно.
- SQLite внутри MQL5 закрывает потребность в локальном журналировании и хранении состояния без внешних БД; OpenCL — путь к GPU-ускорению вычислений прямо в терминале.

## 8. Применение в xauusd-alert-system

### 8.1 Execution (ядро исполнения сигналов)
**Из документа:** транзакционная модель и API ордеров: MqlTradeRequest/MqlTradeResult, OrderCheck, OrderSend/OrderSendAsync, синхронные/асинхронные стратегии (6.4.9–6.4.13, 6.4.35, стр. 1196–1214, 1378–1390).
**Применение:** реализовать в alert-системе единый модуль исполнения: предпроверка (OrderCheck + расчёт маржи) → отправка → обработка retcode → подтверждение через OnTradeTransaction. Для скорости — асинхронная отправка с очередью подтверждений.
**Приоритет:** P0.
**Эффект:** надёжное исполнение сигналов XAUUSD с корректной обработкой реквот/частичного исполнения; устранение «висящих» запросов.

### 8.2 Risk Management
**Из документа:** OrderCalcMargin (6.4.7), OrderCalcProfit (6.4.8), свойства символа SYMBOL_VOLUME_*/SYMBOL_TRADE_TICK_VALUE (6.1), SL/TP-модификация (6.4.15), трейлинг (6.4.16), частичное закрытие (6.4.17), эмуляция депозитов в тестере (6.5.14).
**Применение:** (а) риск-калькулятор объёма: от риска в % депозита через TickValue/TickSize к лотам XAUUSD с округлением к VOLUME_STEP; (б) обязательная предпроверка маржи перед сигналом; (в) SL/TP выставление и трейлинг по книге; (г) лимиты серий убытков через контроль позиций.
**Приоритет:** P0.
**Эффект:** жёсткий контроль риска на сделку; защита от переплечения на волатильном золоте.

### 8.3 Architecture (событийная архитектура)
**Из документа:** события EA: OnTick/OnTimer/OnBookEvent/OnChartEvent, однопоточность и очередь событий (6.4.1, стр. 1170–1171); мониторинг окружения (6.4.37); мультивалютные EA через spy-индикаторы (6.4.38).
**Применение:** перевести логику алертов с таймерного опроса на событийную модель: новые бары/тики XAUUSD → расчёт признаков → модель → сигнал. Если система отслеживает несколько символов — паттерн spy-индикатора.
**Приоритет:** P1.
**Эффект:** снижение латентности сигналов и CPU-нагрузки; корректная работа вне зависимости от активности графика.

### 8.4 Alerts (доставка уведомлений)
**Из документа:** SendNotification (push на мобильный), SendMail, SendFTP (7.5.1+, стр. 1795–1798); WebRequest для HTTP (п. 7.5), лимиты частоты push.
**Применение:** ядро alert-каналов: push-уведомление при срабатывании сигнала (с порогом TradeLevel), e-mail-дайджесты, WebRequest-хуки в Telegram-бот или собственный бэкенд. Криптография 7.4 — для подписи/хранения ключей API.
**Приоритет:** P0.
**Эффект:** немедленная доставка сигналов трейдеру всеми стандартными каналами без внешних зависимостей; обратите внимание на whitelist URL и лимиты push.

### 8.5 Backtesting
**Из документа:** методология 6.5: режимы тиков (реальные тики — эталон), TesterStatistics, OnTester (кастомные критерии), фреймы (6.5.10–11), оптимизационные события, отладка/профилирование.
**Применение:** (а) валидация ML-сигналов XAUUSD в тестере на реальных тиках; (б) кастомный критерий OnTester (например, PF × sqrt(trades) с штрафом за просадку) для перебора порогов сигнала; (в) фреймы для сбора equity-кривых со всех агентов в единый отчёт.
**Приоритет:** P0.
**Эффект:** автоматизированный, воспроизводимый бэктест-контур; отсев слабых моделей до продакшена.

### 8.6 Data Processing
**Из документа:** таймсерии: CopyRates/MqlRates, MqlTick, поиск экстремумов (5.3); индикаторы через хэндлы + CopyBuffer с проверкой готовности (5.5); файлы/SQLite (часть 4, 7.6).
**Применение:** модуль фичагенерации для модели (RSI/MACD/геометрия свечи из книги №1) на CopyBuffer с корректной обработкой асинхронности; SQLite — журнал сигналов и отправленных алертов (идемпотентность, дедупликация).

### 8.7 News filter (управление новостными рисками)
**Из документа:** экономический календарь (7.3): время/важность/валюта события; запрет в тестере (4014); серверное время и DST.
**Применение:** live-режим: блокировка сигналов за N минут до/после важных новостей по USD (для XAUUSD критично: NFP, FOMC, CPI). Для бэктеста — параллельная собственная таблица новостей в SQLite.
**Приоритет:** P1.
**Эффект:** избежание торговых алертов в периоды аномальной волатильности/расширения спредов золота.

### 8.8 Integration (Python/ML-пайплайн)
**Из документа:** пакет MetaTrader5 для Python (7.9): данные котировок/тиков/истории сделок, отправка ордеров, ограничения (нет событий/индикаторов, ошибка 10027).
**Применение:** связка с ML-контуром: Python забирает данные из терминала, делает инференс модели (или переобучение по расписанию), возвращает сигналы в EA через файлы/SQLite/сокеты; торговлю из Python отключить настройкой (10027), оставив исполнение за MQL5-роботом.
**Приоритет:** P1.
**Эффект:** чистое разделение ответственности: Python — ML, MQL5 — исполнение и алерты.

### 8.9 Architecture (расширения платформы)
**Из документа:** OpenCL (7.10) — GPU-вычисления в терминале; кастомные символы (7.2); ресурсы (7.1); проекты (7.8); DLL (7.7).
**Применение:** OpenCL — если инференс нейросети переносится в EA (совместно с библиотекой книги №1); проекты — организация репозитория xauusd-alert-system как MQL5-проекта с разделяемым кодом.
**Приоритет:** P2.
**Эффект:** масштабируемость вычислений и чистая структура кодовой базы.

## 9. Критический анализ

### 9.1 Сильные стороны

- **Полнота и авторитетность.** 2047 страниц официального издания MetaQuotes с 581 разделом — практически полное покрытие языка и API; документ синхронизирован с платформой (редакция 2026 г.).
- **Практико-ориентированность.** Сотни рабочих листингов (папка MQL5Book), включая сложные паттерны: spy-индикаторы тиков, квазитики из стакана, фреймы оптимизации, калькулятор маржи.
- **Глубина торговых тем.** Часть 6 закрывает 95% практических вопросов EA-разработки — от структуры запроса до мультивалютности и асинхронных запросов; часть 6.5 — фактически методичка по валидации торговых систем.
- **Интеграционный периметр.** SQLite, WebRequest/Sockets, Python, OpenCL, криптография — редкий для торговых платформ объём встроенных технологий, всё с примерами.
- **Честные ограничения.** Книга систематически указывает подводные камни: запрет календаря в тестере, DST-особенности, отсутствие событий в Python, whitelist URL, отличия OnBookEvent от OnTick.
- **Структура «учебник + справочник».** Мини-резюме разделов и сквозная нумерация позволяют использовать книгу в обоих режимах.

### 9.2 Слабые стороны / ограничения

- **Только английский язык в данном файле** (переведённые издания распространяются отдельно) — для русскоязычной команды возможен барьер в терминологии.
- **Нет ML-контента.** Нейросети, обучение, метрики качества моделей — вне скоупа; книга №1 (Neural Networks…) является обязательным компаньоном.
- **Мало методологии стратегий.** Как строить/проверять торговые гипотезы (walk-forward, статистическая значимость, множественные тесты) — не рассматривается; это документация языка, а не квант-учебник.
- **Скриншотная иллюстративность.** Все иллюстрации — снимки UI; нет аналитических графиков и диаграмм архитектур — дизайн-решения системы придётся принимать самостоятельно.
- **Привязка к платформе.** Значительная часть решений (события, тестер, календарь) непереносима вне MT5; перенос логики на другой движок потребует перепроектирования.
- **Объём как риск.** 2047 страниц без «быстрого пути» — новичку легко утонуть; требуется маршрут чтения (см. рекомендации).

### 9.3 Вопросы для уточнения

1. Какая версия платформы соответствует примерам книги в деталях (политики исполнения, новые поля структур) — требуется сверка с текущей сборкой MT5 при миграции в прод.
2. Актуальные лимиты SendNotification (частота push) и WebRequest (таймауты, длина ответа) для реальной нагрузки алерт-системы — в книге заданы базовые рамки, нужны замеры.
3. Поведение фреймов (6.5.10–11) при больших объёмах данных с облачных агентов — пропускная способность и надёжность при полном переборе оптимизации.
4. Синхронизация SQLite-журнала сигналов между несколькими терминалами/агентами (если alert-система масштабируется) — книга описывает локальное использование.
5. Точная реплика расчёта маржи/профита для XAUUSD у конкретного брокера (символьные коэффициенты маржи отличаются) — требует сверки с SYMBOL_* конкретного счёта.
6. Ограничения бесплатного облака push-уведомлений MetaQuotes при росте числа пользователей системы.
